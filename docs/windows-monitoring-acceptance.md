## 旧系统统一安装包验收

当发布 `installer/SecurityMonitoring.nsi` 生成的统一安装包时，安装包输入必须同时
包含 `SecurityMonitoring.exe`、`SecurityMonitoringLegacy.exe`、
`SecurityMonitoringModern.exe` 和 `MicrosoftEdgeWebView2RuntimeInstallerX64.exe`；安装时
只在 Win10/11 执行该运行时，完成后删除临时安装文件。
启动器必须按真实系统版本选择客户端：XP SP3 x86、Windows 7、Windows 8/8.1 以及低于
Windows 10 1803（build 17134）的系统进入 Legacy，64 位 Windows 10 1803+/11 进入
Modern，32 位 Windows 10 继续进入 Legacy。旧系统验收不能通过在新系统上启动 Legacy
文件替代。

Legacy 的配置根目录必须与 Modern 一致，均为 `%APPDATA%\com.securitymonitoring.app`；
截图还会按固定盘符轮询写入其他固定盘的 `SecurityMonitoring\records`，不能写入 U 盘、
移动硬盘、光驱或网络盘。
在 Modern 上采集至少一条记录后切换到 Win7/Win8，Legacy 应能读取相同日期目录；在
Legacy 上采集后切换回 Win10/11，Modern 的回放页面应能读取 JPEG 和 JSONL。Legacy
还必须验证：GDI 全虚拟桌面截图、JPEG 可打开、启停状态持久化、锁屏跳过、登录启动、
单实例、事件日志写入、卸载不删除用户记录。

## 构建与安装

在 Windows 10/11 开发机安装 Node、pnpm、Rust MSVC、Visual Studio C++ Build Tools、Windows SDK、
NSIS 和 CMake。现代客户端构建需要 WebView2 离线安装器；首次构建通常由 Tauri 在构建机联网下载。
统一安装器脚本要求预先提供真正的 Evergreen Standalone x64 文件
`MicrosoftEdgeWebView2RuntimeInstallerX64.exe`（不能使用联网 bootstrapper），并设置
`SECURITY_MONITORING_WEBVIEW2_OFFLINE_INSTALLER` 或传入 `-WebView2OfflineInstaller`。

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm build
cargo test --manifest-path src-tauri/monitor-core/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
pnpm desktop:build
```

安装 `src-tauri/target/release/bundle/nsis` 中的 `.exe` 或 `msi` 中的 `.msi`。记录 Windows 版本、显示器布局、缩放比例和应用版本。安装包未签名时，按部署环境的正常安装政策处理。

## 数据位置

点击 logo 10 次并通过密码验证后，通过“监控设置”弹窗中的“打开记录目录”获取实际路径。日期文件夹中的 `captures.jsonl` 与 JPEG 一一核对，不再创建或追加 `events.jsonl`。Windows 日志查看“事件查看器 → Windows 日志 → 系统”，按来源 `SecurityMonitoring` 筛选。

旧版本将应用日志源注册在 Application（应用程序）中。升级后需在设置里重新点击“注册日志源”并允许 UAC；使用新的系统日志源，避免复用旧来源时受 Windows 日志映射缓存影响。旧的应用程序日志及来源不删除。未注册系统日志源时明确报错，不回退写入 Application。微软说明：将同一个来源重新关联到另一日志需要重启系统，参见 [CreateEventSource](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.eventlog.createeventsource)。

没有 Windows 服务；未登录用户、休眠或关机期间不采集屏幕。本地记录目前为 JPEG 和 JSONL，不代表防篡改审计存储。

## 日志字段与文件核对

新截图的 `md5` 为写入 JPEG 文件的完整字节的 MD5，使用 32 位小写十六进制，同时记录于 `captures.jsonl` 和截图成功事件。旧索引缺少该字段时读取为 `null`，不回写虚构校验值。校验及保存耗时包括 MD5 计算、图片落盘和索引落盘；采集及编码耗时包括桌面检查、采集、JPEG 编码及前台信息读取。记录时间是生成存储记录的时间，事件时间是写入日志的时间。

在 Windows 上将路径替换为日志中的完整图片路径，核对结果与日志和索引的 MD5 一致（忽略大小写）：

```powershell
Get-FileHash -LiteralPath 'D:\监控记录\2026-10-13\实际截图文件.jpg' -Algorithm MD5
```

事件 ID：1100 截图成功，1200 截图自动删除。启动、退出、开始/停止、配置修改、暂停、恢复、失败、清理失败和日志源注册都不写入事件。两类事件均为信息级别，并附带版本、进程 ID、运行批次、用户和 Windows 会话 ID。

配置修改仅更新本地设置；删除日志仅在文件实际删除后写成功，索引后续更新失败只在客户端状态中提示。窗口标题仍保留在截图索引中，默认不写入系统日志。
